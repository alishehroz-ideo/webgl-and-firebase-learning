02 Data parsing robustness

Parse by shape, not position.

Position parsing (parts[1]) crashes the moment a field is missing or reordered. Instead I anchor on the date's shape (dd/mm/yyyy) wherever it sits — then read outward. Nothing hardcoded.

CoverInfoParser.cs
// anchor on the DATE by its SHAPE — never by position
static readonly Regex DateRx =
    new Regex(@"^\s*\d{1,2}/\d{1,2}/\d{4}\s*$");

public static ParsedContent Parse(string raw)
{
    var tokens = raw.Split('_');

    int dateIdx = -1;                // find date by shape
    for (int i = 0; i < tokens.Length; i++)
        if (DateRx.IsMatch(tokens[i])) { dateIdx = i; break; }

    if (dateIdx >= 2) {               // [name…][author][date]
        r.Author = Clean(tokens[dateIdx - 1]);
        r.Name   = Clean(string.Join("_", tokens, 0, dateIdx - 1));
    }
    // fewer fields / no date → fallback, low-confidence, no crash
    return r;
}

03 Data loading, caching & error states

Load once from Firebase, handle every state.

One request pulls the whole library; it's parsed once and kept in memory (search is then instant — no re-fetch). Loading and failure are first-class states. (read-only — this feature saves nothing.)

SearchService.cs — Firebase integration
public async Task<bool> LoadAsync()
{
    string json = await FirebaseClient.GetJson(FirebaseEndpoints.StoryLibrary());
    if (string.IsNullOrEmpty(json) || json == "null")
        return false;            // unreachable / empty → error
    try {
        var root = JObject.Parse(json);
        foreach (var s in root.Properties())
            _all.Add(CoverInfoParser.Parse(FindCoverInfo(s)));
        return true;
    }
    catch (Exception e) {       // malformed → error, never a crash
        Debug.LogError(e.Message);
        return false;
    }
}

05 Search performance

Parse once → every search is instant.

The messy strings are parsed a single time when the library loads. After that, each keystroke-search is a plain in-memory scan of the clean list — no network trip, no re-parsing. Fast and smooth for the stated 1,000+ items.

SearchService.cs — Search()
// parse happened ONCE at load; this just scans the clean in-memory list
public List<ParsedContent> Search(string query)
{
    string q = query.Trim().ToLowerInvariant();
    foreach (var item in _all) {
        bool nameHit   = item.Name   != null && item.Name.ToLowerInvariant().Contains(q);
        bool authorHit = item.Author != null && item.Author.ToLowerInvariant().Contains(q);
        if (nameHit || authorHit) results.Add(item);   // name OR author
    }
    return results;
}
Required answer scalability thinking

Scaling to 10,000+ items.

The demo downloads & parses everything in the browser — fine at 1,000, but at 10,000+ that's a big download and CPU jank on every visit. The redesign moves the heavy work off the browser.

✗ simple every visit

Each browser downloads all items and parses all of them on the single WebGL thread — slow, heavy, repeated.

✓ redesign once, on the server

The browser downloads only the matches (e.g. 20). Parsing never happens in the browser again.

1
Precompute a clean index — a Firebase Cloud Function parses the messy data once (and re-runs only on changes) into a separate /searchIndex node. Raw data stays untouched.
2
Server-side, indexed queries — with an .indexOn field, the browser asks orderBy=author&startAt=…&limitToFirst=20; Firebase jumps to the matches — no full scan.
3
Or a search service (Algolia / Typesense) for instant, typo-tolerant, multi-field search at any scale.
06 Key decisions & challenges

The calls that shaped it.

Parse in memory, never at the source

The rule forbids cleaning Firebase. So the app builds a clean copy in its own memory on load — the source stays messy, untouched.

rule: "don't modify the data at the source"

Shape, not position

Anchoring on the date's shape survives reordering, mixed separators and missing fields — where parts[1] would crash.

CoverInfoParser · Regex date anchor · no hardcoding

Real Arabic in WebGL

The data is Arabic. WebGL has no OS font fallback, so I bundled the Amiri font and render with TextMeshPro, plus letter-shaping + RTL.

TextMeshPro + Amiri · ArabicSupport.Fix()

Loading & error as real states

Empty, unreachable, or malformed data all resolve to a clear on-screen message — never a blank screen or a crash.

try/catch → bool → Loading / Error events
